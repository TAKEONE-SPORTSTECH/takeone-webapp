# TAKEONE SCREEN — Android TV

A television that shows a full-screen pairing QR and **never** sleeps.

This is the native counterpart of `https://stage.takeone.bh/screen`: it enrols
itself, stands on the wall showing its pairing code until an organiser scans it,
and then renders whatever board it was adopted as. Same contract, same server,
same look — the difference is the screensaver. An Android TV launcher drops its
daydream over a web page whatever the page asks for, and a screensaver over a
live mat is not a cosmetic problem, so the wake lock has to be held by an app.

## What it does

1. `POST /screen/enroll` → `{token, code}` (CSRF-exempt for exactly this case: a
   device calling in with no session). The token is remembered, so a television
   switched off between competitions comes back as itself.
2. Renders the QR of `/screen/claim/{code}` full screen, with the code printed
   large underneath for whoever has to read it aloud across a hall.
3. Polls `GET /screen/{token}/status` every 4s. `{go: …}` → loads that board.
   `404` → the identity is gone, so it forgets it and enrols again.
4. Holds the screen awake the whole time (`FLAG_KEEP_SCREEN_ON` natively at
   `onCreate`, plus `wakelock_plus` for the life of the app) in immersive
   full-screen with no system chrome.

Nothing here can display a competition on its own — a waiting screen renders its
own pairing code and nothing else, and every claim is an authenticated act on the
organiser's phone. That is the server's rule, not this app's.

## Build

```bash
./setup.sh                       # generates android/, applies the TV overrides
flutter build apk --release --dart-define=TAKEONE_BASE_URL=https://stage.takeone.bh
adb connect <tv-ip>:5555 && adb install -r build/app/outputs/flutter-apk/app-release.apk
```

Verified on Flutter 3.47.1 / Dart 3.13.1 against `/opt/android-sdk`
(compileSdk 36, minSdk 24) — `flutter analyze` clean, 45.8 MB universal APK
carrying arm64-v8a, armeabi-v7a and x86_64. `--split-per-abi` cuts that to
roughly a third if you know the panel; a TV box is almost always arm64.

**The APK is debug-signed.** There is no release keystore for this app, so
`--release` falls back to Android's debug key: fine for sideloading onto a hall
screen, not fine for Play. If it ever needs one, generate a keystore, add a
`signingConfigs` block to `android/app/build.gradle.kts` — and remember `android/`
is regenerated by `setup.sh`, so that block belongs in a committed patch rather
than only in the generated tree.

`TAKEONE_BASE_URL` is compile-time on purpose: a screen bolted to a wall has no
keyboard, so there is no settings page to get wrong. It defaults to **stage**, so
a build is never pointed at production by omission.

The SDK, if this box does not have it yet:

```bash
git clone -b stable --depth 1 https://github.com/flutter/flutter.git /opt/flutter
export PATH="/opt/flutter/bin:$PATH"
export ANDROID_SDK_ROOT=/opt/android-sdk
flutter doctor
```

## On the wall

| | |
|---|---|
| Different screen | **MENU** (or `N` / `R`) on the pairing screen |
| Give the wall back | hold **BACK** for 3s on a live board |
| Screen is awake | the pulsing green dot, bottom-left |
| Can't reach the server | `RECONNECTING` bottom-left — the code stays valid, it keeps trying |

A single BACK press does nothing deliberately: it is the easiest key to hit by
accident on a TV remote, and the screen may be showing a live mat.

## Layout

Authored at 1920×1080 and only ever scaled — the same stage mechanic the web
screens use, so this screen and the board it becomes are the same size on the
wall whatever panel it ends up on.

Typography falls back to the platform face out of the box. To match the web
screen exactly, drop `Anton-Regular.ttf` and `BarlowCondensed-{SemiBold,Bold}.ttf`
into `assets/fonts/` and uncomment the `fonts:` block in `pubspec.yaml`.

## Security notes

- **Destinations are host-locked.** The status endpoint is open by design (a wall
  has nobody signed in to it), so a URL from it is only ever loaded if it lives
  on the host this APK was built for (`Config.trusts`). The WebView refuses
  off-host navigation too — a wall screen that can be walked to an arbitrary
  origin is a billboard.
- **Cleartext is off** (`usesCleartextTraffic="false"`); the base URL must be
  HTTPS.
- **Tokens and codes are validated** against the server's own route constraints
  (40 and 6 alphanumerics) before ever being put into a URL or on the glass.
- The app holds no credentials and can read nothing. Its entire authority is a
  pairing row that may render its own code.

## Layout of the repo

```
lib/main.dart              the three states: starting → waiting → displaying
lib/src/config.dart        which host, how often, what may be loaded
lib/src/screen_client.dart enroll / status / remembered identity
lib/src/pairing_page.dart  the full-screen QR
lib/src/display_page.dart  the board, in a host-locked WebView
lib/src/kiosk.dart         wake lock + immersive full screen
lib/src/theme.dart         the hall palette, taken from the web screens
android_tv/                the manifest, theme, banner and Activity this repo owns
setup.sh                   generates android/ and applies the above
```

`android/` is generated, not committed: it belongs to whichever Flutter version
you build with. Re-run `./setup.sh --force` after a Flutter upgrade.
