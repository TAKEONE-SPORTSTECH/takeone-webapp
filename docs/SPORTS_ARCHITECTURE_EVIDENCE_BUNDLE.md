### Does the frontend calculate scores? — No

The console sends **intentions**, never totals, and renders what the server returns. From `app/Events/Sports/Taekwondo/.../scoreboard/control.blade.php`:

```js
/* ── Talking to the mat ──────────────────────────────────────────────
   Never optimistic. A console showing a point the server did not record is
   worse than one that lags 40ms, because the hall is watching the other
   screen and the two would disagree. */
var busy = false;
function send(command, payload) {
  if (busy) return Promise.resolve();            // ← single-flight guard, client-side only
  busy = true;
  return fetch(URL_CMD, {
    method: 'POST',
    headers: { 'Accept': 'application/json', 'Content-Type': 'application/json',
               'X-CSRF-TOKEN': document.querySelector('meta[name=csrf-token]').content },
    credentials: 'same-origin',
    body: JSON.stringify(Object.assign({ mat: MAT, command: command }, payload || {})),
  }).then(r => r.json().catch(() => ({})))
    .then(d => {
      // A refusal carries the current truth with it. Adopt it either way …
      if (d.state)   { STATE = d.state; received = performance.now(); }
      if (d.queue)   { QUEUE = d.queue; }
      if (d.corners) { CORNERS = d.corners; }
      if (d.state || d.queue) { paint(); }
      if (!d.success) throw new Error(d.message || 'Command failed');
    })
    .catch(e => alertBar(e.message))
    .finally(() => { busy = false; });
}

// Buttons send commands, never arithmetic:
b.onclick     = function () { send('score',   { side: side, action: a.key }); };   // :886
x.onclick     = function () { send('adjust',  { side: side, n: b[1] }); };          // :855
plus.onclick  = function () { send('gamjeom', { side: side, dir: 1 }); };           // :909
el('btnCommit').onclick = function () { send('commit'); };                          // :1334
```

The only client-side arithmetic is the countdown clock, derived from the server-supplied `remaining + running + at` triple. `MatState`'s docblock explains why: *“Every screen computes its own clock from those three, so a screen that joins late is instantly correct… `at` is the server's clock when the state was written; the client measures elapsed against its OWN clock.”*

Sport branching in the frontend: **none found in shared views**. Sport vocabulary appears only in the sport's own views and in the two bout-video review pages (`resources/views/personal/{mobile,desktop}/bout-video.blade.php`, which use `.aka`/`.ao` as CSS class names for the red/blue corner).

1. `config/event_schema.php` → form vocabulary (label, icon, division label, unit, team, belts, samples);
2. `config/combat.php` → `CombatSport` plug-in (weight tables, classification, corners, score labels, officiating roles);
3. `config/event_types.php` → `EventType::owns($event)`, which tests `event_type` **and** `sport`.

Not an enum, not a foreign key, not a table, not polymorphic. Nothing prevents `sport = 'bjj'`; the event simply resolves to `GenericEvent`.

### Ruleset / versioning approach

**There is none.** Rules live in two places, neither persisted with the result:

- **PHP constants** — `MatState::ACTIONS`, `MatState::PENALTIES`, `POINT_GAP = 12`, `GAM_JEOM_LIMIT = 5`.
- **Runtime toggles inside the cached mat state** — Karate's `rules` command sets `senshuRule`, `autoSenshu`, `winByPenalties`, `atoshiWarn`, `gapOn`, `gap`, `warning`.

Consequence: a committed result records a winner and a score string, but **not which rule variant produced it**, and the toggles vanish with the cache entry. A disputed bout cannot be re-derived from stored data.

### Audit evidence

`event_match_events` is a genuine append-only officiating log — the strongest data-integrity asset in the schema. Its own migration explains the design (full text in §12). Key properties: one row per command; `payload` kept verbatim; running score denormalised per row; millisecond `occurred_at`; `match_id` survives bout deletion; `sequence` monotonic-but-not-unique so a clash can never throw inside a live request. It is written by `MatchEventLog` and read back only by `App\Media\BoutTimeline` (video markers) — **never by the scoring path**.

## 8. Live Scoring, Realtime, and Scoreboard Flow

### Confirmed source-to-display flow

```
[1] OPERATOR  app/Events/Sports/<Sport>/Tournament/resources/views/scoreboard/control.blade.php
              send('score', {side, action})  →  POST, single-flight guard, never optimistic

[2] ROUTE     routes/web.php  POST /taekwondo/control/{event:uuid}   (taekwondo-scoreboard.command)
              or              POST /taekwondo/court/{token}/command  (…token-command)

[3] AUTHZ     ScoreboardController::command()
                abort_unless($this->canScore($event), 403)   → EventAccess::canScore()
                abort_unless($event->sport === '<sport>', 404)
              token path: controlDevice() → device claimed, surface==='control',
                          re-checks canScore() for the pairing organiser,
                          forces $request['mat'] = $device->court

[4] VALIDATE  $request->validate([...])  command ∈ Scoring::COMMANDS, side ∈ aka|ao,
                                         action ∈ keys(MatState::ACTIONS), bounds on n/minutes/remaining,
                                         free text length-capped (it lands on a public wall)
              abort_unless($this->matExists($event, $data['mat']), 404)

[5] RULES     Scoring::apply()  →  MatState::load()  →  settleClock()  →  match($command) → …
                                   score() · gamjeom() · checkRoundEnd() · awardRound() · undo()

[6] AUDIT     MatchEventLog::record(sport, command, payload, matchId, scoreA, scoreB)
              → INSERT event_match_events            (best-effort; never throws)

[7] CAMERAS   CameraFleet::observe(event, court, command, matchId, bout)   (best-effort)

[8] PERSIST   $state->save()  →  Cache::put(key, toArray(), now()->addMinutes(240))
                                 ⚠ the file cache, NOT the database

[9] PUSH      ScreenChannel::notifyCourt($event, $mat, ['action'=>'mat','state'=>…])
              → Realtime()->publishMany([...])  (MQTT, wrapped in rescue())
              load|commit|clear additionally rebuild the board payload for the mat (or all mats)

[10] DISPLAY  court-display/partials/screen-link.blade.php — hand-written MQTT 3.1.1 client
              in a Web Worker, subscribe-only:
                {action: paired|unpaired}    → reload
                {action: board, payload:{}}  → redraw in place
              court-display/board.blade.php — 60s heartbeat GET {statusUrl}; claimed===false → reload

[11] COMMIT   Scoring::commit() → EventTypeRegistry::for($event)->recordOutcome(…)
              → Tournament::recordOutcome() → Advancement::record()  (writes event_matches, advances)
              → CallNotifier::pushResult/pushDue → ScreenChannel::notifyCourt(ALL mats)
              → broadcast(['action'=>'outcome'|'podium', …])   (MQTT to the event's audience)
              → then auto-loads the next runnable bout from RunningOrder::matQueue()
```

### Source-of-truth observations

- **Laravel is authoritative — confirmed by code and by explicit design comments.** The console posts intentions; all arithmetic and every rule run in `Scoring::apply()`. Karate even sends the *derived* leader rather than letting the client recompute the senshu tie-break.
- **The truth is stored in the file cache, not the database.** `MatState` is a `Cache::` blob with a 240-minute TTL. Its docblock defends this (a running score is scaffolding; the *result* is written by `recordOutcome`), but it means an in-progress bout has no durable home, and `CACHE_STORE=file` is node-local.
- **No idempotency key, no locking, no optimistic concurrency.** Grep for `lockForUpdate|If-Match|idempotency|version` across the scoring path yields nothing. `Cache::get` → mutate → `Cache::put` is a read-modify-write with last-write-wins. The only guard is the client-side `busy` flag in `send()`, which protects one browser tab and nothing else.

### Audit / undo / reversal evidence

| Capability | State | Evidence |
|---|---|---|
| Append-only command log | ✅ | `event_match_events` + `MatchEventLog::record()` |
| Log guaranteed | ❌ | Every path wrapped; failures swallowed and logged; disable-able via `config('events.match_log')` |
| Log read back by scoring | ❌ | Only `App\Media\BoutTimeline` consumes it |
| Undo | ⚠️ in-memory | TKD `Scoring::undo()` pops a stack held inside the cached state, `LOG_LIMIT = 12`; Karate uses inverse commands (`undo_point`, `penalty {dir:-1}`) |
| Undo is audited | ✅ | The undo is itself recorded as a command row (`test_taking_a_point_back_is_recorded_as_its_own_row`) |
| Reversal after commit | ❌ / not found | `recordOutcome()` refuses on a finished event: `abort_if($event->hasEnded(), 422)`. No amend-committed-result path found |
| Ruleset stamped on result | ❌ | See §7 |

### Operator / public display evidence

- **Stale-console recovery is deliberate:** a refused command returns `422` **with the current state, queue and corners attached**, and the client adopts it. This is the closest thing to concurrency handling in the system — it corrects a lagging console, but does not prevent two consoles from both writing.
- **Screen recovery:** reload on `paired`/`unpaired`, redraw on `board`, plus an independent 60s heartbeat so an unpaired screen returns to its code within the minute.
- **Why a Web Worker:** the partial's docblock records measured evidence — an inbound socket message on the main thread waited *minutes* behind paint work on a low-powered display versus seconds headless; a Worker has its own thread. Also explains why `mqtt.js` (369 KB) was rejected for an appliance on a metered link in favour of an inlined subset of MQTT 3.1.1.

```php

namespace App\Events\Contracts;

/**
 * An event type as a self-contained package (CLAUDE.md → "Events Are
 * Self-Contained Packages").
 *
 * One implementation owns the ENTIRE vertical for one kind of event: what it
 * stores, what it asks for at creation, who may enrol and under what gate, its

 *
 * Controllers resolve a package from the registry and delegate. A controller,

 * `$event->event_type` to decide behaviour — that decision belongs here.
 *

 * tests. No shared-code edit.

    /* ---------------- Identity ---------------- */
    public function key(): string;                 // "taekwondo_tournament"
    public function label(): string;
    public function owns(ClubEvent $event): bool;  // registry asks in order; first match wins

    /* ---------------- Schema & creation input ---------------- */
    public function validationRules(?ClubEvent $event = null): array;
    public function formSections(): array;
    public function formCatalog(): array;          // weight tables, belt ladders, fixture templates
    public function columnsFromInput(array $data, ?ClubEvent $event = null): array;
    public function saveRelatedData(ClubEvent $event, array $data): void;

    public function enrolmentGate(ClubEvent $event, User $user, ?ClubEventRegistration $existing = null): EnrolmentDecision;
    public function classifyEntry(ClubEvent $event, ClubEventRegistration $registration): ?EventCategory;
    public function onEntrantsChanged(ClubEvent $event, ?EventCategory $category = null): void;

    /* ---------------- Lifecycle ---------------- */
    public function stage(ClubEvent $event): string;                       // draft·enrolling·weigh_in·drawn·running·completed
    public function canTransitionTo(ClubEvent $event, string $stage): bool; // "Enforced server-side"
    public function stages(): array;

    /* ---------------- Engine ---------------- */
    public function recordOutcome(ClubEvent $event, int $unitId, array $payload): array;
    public function performAction(ClubEvent $event, string $action, array $payload = []): array;
    public function availableActions(ClubEvent $event): array;

    /* ---------------- Realtime ---------------- */
    /**
     * Everyone who must be told live when this event changes — user ids.
     * Packages MUST fan out over MQTT from inside their own write paths
     * (`recordOutcome`, `performAction`, `onEntrantsChanged`) … Publishing is
     * best-effort; the DB stays the source of truth.
     */
    public function audienceFor(ClubEvent $event, string $reason = 'update'): array;
    public function notificationSchedule(ClubEvent $event): array;   // Milestone[]

    /* ---------------- Outputs ---------------- */
    public function results(ClubEvent $event): array;
    /**
     * May a manager type the winners in by hand?
     * False for types that DERIVE their result from their own engine (a
     * bracket, a league table) — for those, hand-entry would let a manager
     * publish a podium that contradicts the recorded matches, so the write
     * path must refuse it server-side.

    public function allowsManualResults(): bool;
    public function timeline(ClubEvent $event): array;
    public function nextUp(ClubEvent $event, User $athlete): ?array;
    public function rosterRows(ClubEvent $event): array;

    /* ---------------- Financials & display ---------------- */
    public function finance(ClubEvent $event): array;
    public function views(): array;      // ['show' => ['mobile' => …, 'desktop' => …], …]
    public function viewData(ClubEvent $event, User $viewer): array;
    // (plus hallScreens(), matPanel(), reloadHallScreens(), runData(), bracketView()
    //  supplied with defaults by AbstractEventType)
}
```

### `app/Events/EventTypeRegistry.php`

**Why included:** The resolution mechanism — how the system decides which package owns an event. Small enough to include whole.

**Inclusion type:** Full file

```php
<?php

namespace App\Events;

use App\Events\Contracts\EventType;
use App\Models\ClubEvent;

/**
 * Resolves the package that owns an event, from config/event_types.php.
 *
 * Generalises the combat-sport registry (App\Sports\Combat\SportRegistry) from
 * "which sport" to "which event type" … Packages are asked in declaration order
 * and the first to claim the event wins, so specific packages must be listed
 * above the fallback.
 */
class EventTypeRegistry
{
    /** @var array<string, EventType>|null */
    private ?array $resolved = null;

    /** @return array<string, EventType> keyed by package key */
    public function all(): array
    {
        return $this->resolved ??= collect(config('event_types.types', []))
            ->map(fn ($class) => app($class))
            ->mapWithKeys(fn (EventType $t) => [$t->key() => $t])
            ->all();
    }

    public function get(?string $key): ?EventType
    {
        return $key ? ($this->all()[$key] ?? null) : null;
    }

    /**
     * The package that owns this event. Never returns null — an event whose
     * type has no dedicated package falls back to the generic package so the
     * app keeps working while types are ported one at a time.
     */
    public function for(ClubEvent $event): EventType
    {
        foreach ($this->all() as $type) {
            if ($type->owns($event)) {
                return $type;
            }
        }

        return $this->fallback();
    }

    public function fallback(): EventType
    {
        return app(config('event_types.fallback'));
    }

    /** Packages a member may pick from when creating an event, for the type picker. */
    public function selectable(): array
    {
        return collect($this->all())
            ->map(fn (EventType $t) => ['key' => $t->key(), 'label' => $t->label()])
            ->values()->all();
    }
}
```

**Notes:** Full file, unmodified. No secrets. Note `for()` never returns null — an unclaimed event silently becomes `GenericEvent`, which is how a BJJ event degrades.

### `app/Events/Sports/Taekwondo/Tournament/Scoreboard/MatState.php`

**Why included:** The live match-state model — the single most architecturally consequential file, because it defines *where the truth lives during a bout* and encodes the sport's round structure.

**Inclusion type:** Sanitized excerpt (docblock + constants + persistence; the 40-property constructor and `toArray()` abridged)

```php
<?php

namespace App\Events\Sports\Taekwondo\Tournament\Scoreboard;

use Illuminate\Support\Facades\Cache;

/**
 * What one Taekwondo mat is showing right now, and the score on it.
 *
 * Deliberately NOT a table … a bout's running score is worth nothing once the
 * bout is over — the result is recorded through recordOutcome() like every
 * other result in the product … A row per point would be a write per keypress
 * on the busiest path in the hall, for data nobody reads after.
 *
 * It cannot be memory-only either: a wall screen reloads … So it lives in the
 * cache — survives a reload, expires on its own, costs no schema.
 *
 * ── Why this is not Karate's MatState with different words ──────────────────
 * A WKF bout is one continuous three minutes with a single score. A WT kyorugi
 * match is a best-of series: each ROUND has its own score and its own gam-jeom
 * count, both reset between rounds, and the match is won by winning rounds …
 * Two athletes can therefore finish 5–20 down on aggregate and still win 2–1.
 *
 * ── The timer ───────────────────────────────────────────────────────────────
 * Stored as `remaining` + `running` + `at`, never as a countdown something has
 * to tick. Every screen computes its own clock from those three, so a screen
 * that joins late is instantly correct, two screens on a mat never drift, and
 * nothing runs server-side between the start and the stop.
 */
class MatState
{
    public const MODE_UPCOMING = 'upcoming';   // the queue — no bout loaded
    public const MODE_VS = 'vs';               // the introduction
    public const MODE_SCOREBOARD = 'scoreboard';

    public const PHASE_ROUND = 'round';
    public const PHASE_REST  = 'rest';
    public const PHASE_GOLDEN = 'golden';      // sudden death, first point wins

    /** A match is minutes long; this only has to outlive a reload. */
    private const TTL_MINUTES = 240;

    /**
     * What a scoring action is worth … the values are WT's: the reward scales
     * with how hard the technique is to land, which is why a turning head kick
     * is worth five punches.
     */
    public const ACTIONS = [
        'punch'     => ['value' => 1, 'label' => 'PUNCH'],
        'body'      => ['value' => 2, 'label' => 'BODY KICK'],
        'head'      => ['value' => 3, 'label' => 'HEAD KICK'],
        'turn_body' => ['value' => 4, 'label' => 'TURNING BODY'],
        'turn_head' => ['value' => 5, 'label' => 'TURNING HEAD'],
    ];

    /** A round ends the moment one athlete leads by this much. */
    public const POINT_GAP = 12;

    /**
     * Gam-jeom that end the MATCH — the opponent wins by punitive declaration.
     * Counted across the whole match, not per round.
     */
    public const GAM_JEOM_LIMIT = 5;

    public function __construct(
        public string $mode = self::MODE_UPCOMING,
        public ?int $matchId = null,
        public ?string $matchNo = null, public ?string $stage = null,
        public ?string $division = null, public ?string $category = null,
        public ?string $tournament = null, public ?string $courtLabel = null,
        public ?string $referee = null,
        public array $aka = [], public array $ao = [],
        /** THIS ROUND's score and gam-jeom. Both reset at every round break. */
        public int $akaScore = 0, public int $aoScore = 0,
        public int $akaGam = 0,   public int $aoGam = 0,
        /** Rounds won — the match itself. */
        public int $akaRounds = 0, public int $aoRounds = 0,
        public int $round = 1, public int $rounds = 3,
        public string $phase = self::PHASE_ROUND,
        public float $remaining = 120.0, public float $duration = 120.0,
        public float $restDuration = 60.0,
        public bool $running = false,
        public bool $finished = false,      // the ROUND is over
        public bool $matchOver = false,     // the MATCH is over
        // … ~15 further properties (undo stack, last event, reveal flags) elided
    ) {}

    public static function load(ClubEvent $event, string $court): self
    {
        $raw = Cache::get(self::key($event, $court));
        // … hydrate from array
    }

    public function save(ClubEvent $event, string $court): self
    {
        Cache::put(self::key($event, $court), $this->toArray(), now()->addMinutes(self::TTL_MINUTES));
        return $this;
    }
}
```

### `app/Events/Sports/Taekwondo/Tournament/Scoreboard/Scoring.php`

**Why included:** The rules engine and the single funnel every scoring command passes through — where authorization-cleared intent becomes state, audit and realtime.

**Inclusion type:** Sanitized excerpt — the command vocabulary, `apply()` in full, and two rule methods. (~800 further lines of rule implementation omitted.)

```php
<?php

namespace App\Events\Sports\Taekwondo\Tournament\Scoreboard;

/**
 * Applies what an official does at the table to the state of a Taekwondo mat.
 *
 * Every rule lives here rather than in the control page's JavaScript, for one
 * reason: the control page is not the only thing that can be wrong. A second
 * official opening the page, a laptop reconnecting mid-match, a screen catching
 * up after a dropped socket — all of them must arrive at the SAME score, and
 * they only do if the state is computed in one place and pushed out.
 *
 * The control page therefore sends intentions ("aka landed a turning head
 * kick"), never results ("aka now has 12"). A client that has fallen behind
 * cannot overwrite the truth with a stale total.
 */
class Scoring
{
    /** Every command an official can issue. Anything else is rejected. */
    public const COMMANDS = [
        'load', 'start', 'pause', 'score', 'adjust', 'gamjeom', 'time', 'rest',
        'award_round', 'golden', 'reset_round', 'reset', 'undo', 'finish',
        'refresh', 'clear', 'commit', 'duration', 'rounds', 'corner', 'meta',
    ];

    private const LOG_LIMIT = 12;   // undo-stack depth, held inside the cached state

    public function apply(ClubEvent $event, string $court, string $command, array $payload = []): MatState
    {
        $state = MatState::load($event, $court);

        if (in_array($command, self::NEEDS_BOUT, true) && ! $state->matchId) {
            throw new \RuntimeException(__('event-taekwondo_tournament::messages.commit_no_bout'));
        }

        // The clock is stored as "remaining as of a moment"; before anything
        // else touches it, bring it up to now.
        $this->settleClock($state);

        match ($command) {
            'load'  => $this->load($event, $court, $state, (int) ($payload['match_id'] ?? 0), $payload),
            'start' => $this->start($state),        'pause'  => $this->pause($state),
            'score' => $this->score($state, $payload),
            'adjust' => $this->adjust($state, $payload),
            'gamjeom' => $this->gamjeom($state, $payload),
            'award_round' => $this->awardRound($state, $payload),
            'golden' => $this->golden($state),      'undo'   => $this->undo($state),
            'commit' => $this->commit($event, $court, $state),
            // … time, rest, reset_round, reset, finish, refresh, clear, duration, rounds, corner, meta
            default => null,
        };

        // Append the command to the officiating timeline … so no caller can
        // reach the scoreboard without passing through here. Corners are handed
        // over as neutral sides: aka is 'a', ao is 'b'.
        // This call cannot throw; a mat must never stop because an audit row did not insert.
        MatchEventLog::record(
            event: $event, court: $court, sport: 'taekwondo',
            command: $command, payload: $payload, matchId: $state->matchId,
            scoreA: $state->akaScore, scoreB: $state->aoScore,
        );

        // The cameras on this mat, if any, are told the same thing the hall is.
        CameraFleet::observe(event: $event, court: $court, command: $command,
            matchId: $state->matchId,
            bout: ['number' => $state->matchNo, 'stage' => $state->stage,
                   'red' => $state->aka['name'] ?? null, 'blue' => $state->ao['name'] ?? null]);

        return $state->save($event, $court);
    }

    private function score(MatState $state, array $payload): void
    {
        $side = $this->side($payload);
        $action = (string) ($payload['action'] ?? '');

        if (! $side || ! isset(MatState::ACTIONS[$action]) || ! $this->scoringOpen($state)) {
            return;                       // ← silently ignored, not an error
        }

        $n = MatState::ACTIONS[$action]['value'];
        $field = $side.'Score';
        $state->$field += $n;

        $state->lastEvent = ['side' => $side, 'n' => $n, 'label' => …, 'ts' => $this->now()];
        $this->push($state, ['type' => 'score', 'side' => $side, 'n' => $n], …);   // undo stack

        $this->checkRoundEnd($state);
    }

    /**
     * A gam-jeom, given or taken back.
     * It is two things at once and both have to move together: a mark against
     * the athlete who earned it, and a point to the other one.
     */
    private function gamjeom(MatState $state, array $payload): void
    {
        $side = $this->side($payload);
        if (! $side || ! $this->scoringOpen($state)) { return; }

        $dir   = ((int) ($payload['dir'] ?? 1)) >= 0 ? 1 : -1;
        $other = $side === 'aka' ? 'ao' : 'aka';
        $gam   = $side.'Gam';
        $before = $state->$gam;

        $state->$gam = max(0, min(MatState::GAM_JEOM_LIMIT, $before + $dir));
        if ($state->$gam === $before) { return; }

        $opponent = $other.'Score';
        $state->$opponent = max(0, $state->$opponent + $dir);

        $this->push($state, ['type' => 'gamjeom', 'side' => $side, 'dir' => $dir], …);
        $this->checkRoundEnd($state);
    }

    /**
     * End the round when the rules end it — and award it, because in these
     * cases the rules also say WHO won:
     *   · gam-jeom ceiling — five hands it to the opponent, full stop
     *   · point gap        — twelve clear, the round is stopped and won
     *   · golden round     — the first point of any kind takes the match
     * A rule the software knows and the screen does not show is worse than no rule.
     */
    private function checkRoundEnd(MatState $state): void { /* … ~55 lines … */ }

    private function commit(ClubEvent $event, string $court, MatState $state): void
    {
        if (! $state->matchId)  { throw new \RuntimeException(__('…commit_no_bout')); }
        $winner = $state->matchWinner();
        if (! $winner)          { throw new \RuntimeException(__('…commit_undecided')); }

        app(EventTypeRegistry::class)->for($event)->recordOutcome($event, $state->matchId, [
            'winner'  => $winner === 'aka' ? 'a' : 'b',
            'a_score' => (string) $state->akaRounds,      // ← ROUNDS for TKD; POINTS for Karate
            'b_score' => (string) $state->aoRounds,
            'status'  => 'done',
        ]);

        // Straight into the next one — the SAME queue the wall board announces.
        $order = new RunningOrder;
        $next  = $order->matQueue($event, $court)
            ->first(fn (EventMatch $m) => $m->id !== $state->matchId && $order->isRunnable($m));

        $next ? $this->load($event, $court, $state, $next->id, [...]) : $this->clear($state);
    }
}
```

```php
        'courtLabel' => ['nullable','string','max:20'], 'stage' => ['nullable','string','max:40'],
        'referee' => ['nullable','string','max:60'],
    ]);

    // The mat must be one this event actually runs — not a string the caller
    // made up, which would mint cache entries at will.
    abort_unless($this->matExists($event, $data['mat']), 404);

    try {
        $state = $this->scoring->apply($event, $data['mat'], $data['command'], $data);
    } catch (\RuntimeException $e) {
        // A refusal the official needs to read and act on. Not a fault.
        // The CURRENT state rides along with it … Handing back the truth lets
        // a console that has fallen behind correct itself on the spot.
        return response()->json([
            'success' => false, 'message' => $e->getMessage(),
            'state'   => MatState::load($event, $data['mat'])->toArray(),
            'queue'   => $this->queue($event, $data['mat']),
            'corners' => $this->corners($event, $data['mat']),
        ], 422);
    }

    // Three commands change WHICH match is on the mat … COMMIT goes to every
    // mat, the other two only to this one: a result carries its winner into a
    // next-round slot the scheduler is free to have placed on another mat.
    if (in_array($data['command'], ['load', 'commit', 'clear'], true)) {
        ScreenChannel::notifyCourt($event, $data['command'] === 'commit' ? null : $data['mat']);
    }

    // Every screen on this mat, immediately. Best-effort like every other push
    // in the app: the cache is the truth and a screen that missed this
    // re-fetches on reconnect.
    ScreenChannel::notifyCourt($event, $data['mat'], ['action' => 'mat', 'state' => $state->toArray()]);

    return response()->json([
        'success' => true, 'state' => $state->toArray(),
        'queue' => $this->queue($event, $data['mat']),
        'corners' => $this->corners($event, $data['mat']),
    ]);
}
```

```php
use ReflectionClass;

/**
 * Makes each sport's folder — and each event type inside it — self-contained.
 * Both levels are discovered from the registry and bound automatically, so no
 * package path is ever written by hand and a sport folder stays portable.
 */
class EventPackageServiceProvider extends ServiceProvider
{
    public function boot(): void
    {
        $registry = $this->app->make(EventTypeRegistry::class);

        $packages = $registry->all();

            }
        }
```

## 13. Inspection Limitations

The following could **not** be confirmed by static inspection and would need a running system, a database, real users, a live broker or deployment access:

1. **Nothing was executed.** No `php artisan` command (including `route:list`, `migrate`, `tinker`), no test run, no `npm run build`, no queue worker, no database query, no MQTT connection. Route facts come from reading `routes/web.php`; **route caching and any dynamically registered routes cannot be ruled out from source alone** (no `Route::` calls inside service providers were found for the sports domain, but the whole provider tree was not exhaustively traced).
2. **Runtime package resolution is unverified.** Which `EventType` actually claims a given production event, how many events carry each `sport` value, and whether any BJJ event exists today are database questions. Not confirmed from repository inspection.
3. **Realtime delivery is unverified.** That MQTT actually connects, that screens receive `{action:'mat'}` within a frame, and that the Web Worker client works on the production appliances are runtime facts. Only the publish/subscribe code paths were read. The performance figures quoted in `screen-link.blade.php` (~2m50s throttled timers; minutes vs seconds for main-thread delivery) are **the authors' measurements as recorded in comments**, not independently verified here.
4. **Concurrency behaviour is inferred from absence.** The claim “no locking/idempotency/version check” is based on an exhaustive grep of the scoring path; it was not demonstrated by firing concurrent requests.
5. **Cache semantics.** `CACHE_STORE=file` was read as a driver name from the working tree's `.env`. Production may differ; deployment configuration was not accessed.
6. **Alpine.js delivery is unconfirmed.** Alpine is used pervasively in Blade but is absent from `package.json`; whether it loads via CDN or a layout include was not traced.
7. **Two very large files were read only in the regions relevant to this bundle** — `app/Http/Controllers/PersonalEventController.php` (3,535 lines) and the two `control.blade.php` pages (1,796 / 1,427 lines). Statements about them are scoped to what was read.
8. **Native apps were catalogued, not audited.** `mobile/` (Capacitor) and `TV/` (Flutter kiosk + camera) are WebView/kiosk shells over this same backend; their source is out of scope here.
9. **Duplication figures are line-diff measurements** after normalising the sport name out of both files. They quantify textual identity, not semantic equivalence — a reviewer planning an extraction should re-verify per file.
10. **Working tree, not `HEAD`.** `git status` showed ~297 modified/untracked paths at inspection time (unrelated in-progress work). This bundle describes the working tree; some content may differ from what is committed on `development` or deployed to production.
11. **Security findings are static-analysis only.** No penetration testing, no dependency CVE scan, no runtime authorization probing was performed.
12. **`Documentation/SUPER_ADMIN_CREDENTIALS.md` was confirmed to exist and to be git-tracked; its contents were not read beyond confirming a credential field is present, and nothing from it is reproduced.** Marked `[REDACTED]`.
